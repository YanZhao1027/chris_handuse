# Chris Handuse / TENDON
Experimental tendon-driven robot hand simulation and in-hand manipulation research.

This repository preserves the iterative research project, including unsuccessful experiments. It is a simulation research prototype, not a manufactured robot or a hardware-validated controller.

## Development history
| Stage | Experiment | Evidence and limitations |
|---|---|---|
| V1 | Interactive kinematic hand | 20 modeled joint axes; no physics |
| V2 | MuJoCo grasp and lift | Five fixed tendons plus five yaw servos; contact physics and free-object lift |
| V3 | CPU PPO | Learned grasp residuals |
| V4 | GPU MuJoCo Warp PPO | 89.6% on full-perturbation independent grasp test |
| V5 | Sphere/ellipsoid manipulation | Rotation PPO failed; retained as a negative result |
| V6 | Elongated ellipsoid | GPU-searched differential command, -15 degree rotation |
| V7 | Rounded cylinder | Independent CPU -15 degree trials; rounded end caps |
| V8 | Flat cylinder, bidirectional PPO | 95/96 on +/-15 degree CPU blind set, but finger-finger collision was disabled |
| V9 | Self-collision-aware manipulation | Actual self-contact constraints; independent +/-15 degree blind 48/96 (negative 48/48, positive 0/48); +/-30 degree failed |

V8's reported success is not evidence for a collision-valid physical hand. V9's thumb mounting and collision fixes substantially reduced interpenetration, but the current thumb still does not reliably oppose the four fingers from the opposite side of the rod.

## Reproduction
The historical folders retain their relative layout because Python scripts import prior models and checkpoints. Use a Python 3.12 environment with MuJoCo 3.8.1, a compatible mujoco-warp / Warp / CUDA PyTorch installation, NumPy and SciPy. See individual stage READMEs. GPU experiments need a compatible NVIDIA GPU. All training and evaluation is local; no API keys are required.
For interactive replays, install the upstream MIT-licensed teardown build utility (https://github.com/elvarofficial/teardown) separately, then run its sims/build.mjs with the desired replay source directory from the corresponding stage directory. The HTML build outputs and optimizer resume states are intentionally not tracked. Replay sources and recorded physics data are included.

Key files: physics-v2/model.py; rl-v3/env.py; gpu-v4/gpu_env.py; rod-v8/runs/assessment/blind.json; rod-v9/runs/assessment/blind.json; rod-v9/runs/preview-audit.json. Checkpoints are generated by this project. Use weights_only=True when loading PyTorch checkpoints.

## Next stage
Redesign the thumb as a physically opposing digit, verify opposing contact normals and nonpenetration after fixture removal, then train a new grasp/rotation policy. Do not treat a four-finger hook grasp as an opposed grasp.

## V10 snapshot: opposed thumb
See [opposition-v10](opposition-v10/README.md). The new thumb mount passed 32/32 independent CPU opposed-grasp trials and the 64-world GPU hold probe. Rotation search found no successful demonstrations under the new criterion; the bounded PPO run has been launched with a searched-action prior. No claim of learned rotation yet. Exact collision-geometry replay is included.
